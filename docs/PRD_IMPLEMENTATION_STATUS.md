# Forecast Research PRD v2.3 implementation status

Current authoritative requirements are `docs/FORECAST_RESEARCH_PRD_v2.3.md` and `docs/FORECAST_RESEARCH_IMPLEMENTATION_PLAN_v1.0.md`. The 30-item engineering acceptance is generated by `scripts/validate_prd_v23_acceptance.py`. Statistical claims remain independently data-gated.

## Implemented

- GitHub Repository as code/config/test/workflow source of truth.
- GitHub Actions reference execution and verification environment.
- PIT recorder with raw payload hash, versions, Git SHA and workflow run ID.
- Canonical durable persistence migrated from quota-limited Neon to self-hosted PostgreSQL 18 on the existing Bangkok VPS, reachable only through the existing authenticated SSH tunnel; artifact-only mode remains explicitly degraded.
- Data-health model: coverage, stale flags, errors, source status.
- Credential-free ETH-native public baseline: Coin Metrics Community MVRV/supply/exchange-supply plus DefiLlama Ethereum stablecoin-supply change; provider timestamps/provenance preserved.
- Public data expansion: Farside US spot-ETH ETF daily net flow plus Coin Metrics aggregate ETH exchange inflow/outflow and active-address/fee/transaction activity evidence; exchange netflow + ETF flow contribute to Capital Flow while activity/gross-issuance diagnostics do not inflate Structural Supply coverage.
- Dune retained as optional enrichment for semantically distinct CEX/staking flows; a Dune tier failure no longer invalidates independent public baseline metrics.
- Six-dimensional Market State Vector: Trend, Valuation, Capital Flow, Crowding, Structural Supply, Volatility/Risk.
- Feature clustering to prevent MA/MACD/RSI-style duplicated evidence from entering the forecast as separate model layers.
- Normalization utilities: rolling percentile, robust z-score, expanding percentile.
- HMM Regime Engine with deterministic fallback and observation schema: return, realized volatility, volume change, OI change.
- 3D / 7D / 30D forecast framework.
- Historical base-rate → momentum → technical/risk → +regime → +flow → +structural → +valuation model ladder.
- Walk-forward evaluation and time-respecting calibration split.
- Probability calibration using isotonic calibration.
- Brier Score, Log Loss, Accuracy, Precision, Recall, Calibration Error, Base Rate lift.
- Ablation and feature-correlation reporting.
- Kill criteria utilities for HMM complexity and ETH proxy validation.
- Model/feature drift checks.
- Level 1 structural, Level 2 probability-shift, Level 3 risk/data alerts.
- Four-page static Dashboard artifact: Overview, State Explorer, Model Lab, Data Health.
- CI, Scheduled Monitor, Backtest, and Model Validation workflows.
- Hourly Scheduled Monitor watchdog with fail-safe stale-run detection, duplicate-run suppression, auditable report artifact, and recovery dispatch through the canonical monitor workflow.
- Reliable external sampling clock: Mac mini launchd polls every 5 minutes and uses UTC :15 nominal buckets to dispatch exactly one 4H Strategic attempt on boundary hours or one independent 1H Tactical attempt on non-boundary hours. This avoids macOS local-time offset errors and prevents a failed 4H bucket from blocking later 1H sampling. GitHub watchdogs provide recovery/System Health alerts, and a daily 24H reliability audit reports coverage, missing/duplicate buckets, and P95 dispatch delay. PostgreSQL outages explicitly degrade to GitHub-artifact state recovery + artifact-only PIT rather than silently stopping computation; 4H confirmation becomes WAIT when missing/stale while material 1H alerts remain eligible. A six-hour PostgreSQL recovery watch now checks the BKK durable store through the same SSH tunnel, stores availability state in GitHub artifacts, and sends exactly one RECOVERED TG notification on unavailable→available; the next normal production run automatically resumes POSTGRES after its own preflight.
- Shadow forecast workflow fail-closes when durable PostgreSQL is unavailable: it records SKIPPED_PERSISTENCE_UNAVAILABLE, creates/settles no forecasts, and does not advance research evidence until persistence recovers.
- Weekly PIT-backed ETH single-asset sizing research checkpoint comparing fixed, conviction-scaled, and volatility-targeted policies; 250 clean intervals trigger human review only and never automatic promotion/execution.
- Unified weekly `research-gates.json` snapshot for forecast readiness, sizing readiness, effective Production Approval, PIT freshness/data health, and one monitor-facing next-action state.
- Candidate model promotion remains manual through PR/review even after statistical gates pass.

## Intentionally gated by real data

The following are implemented but must remain `UNAVAILABLE`, `GATED`, or descriptive until empirical gates pass:

- calibrated 3D/7D/30D production probabilities before enough PIT observations exist;
- HMM participation in prediction before regime ablation proves incremental OOS value;
- ETH-native metrics not supplied by the public baseline (for example independent valuation evidence beyond MVRV and exact staking netflow) until a semantically matching provider is available;
- self-developed ETH cost-basis/SOPR-like proxy before benchmark validation;
- automatic candidate-model promotion (prohibited; human-reviewed PR is required).

This is not an incomplete implementation: fail-closed behavior is part of the PRD. The system must not manufacture probability or reliability when evidence is insufficient.


## v2.3 closure controls

- Immutable experiment/model artifact identity with dataset/config/artifact hashes.
- Persistent lifecycle, Shadow-only promotion path, automatic demotion, Emergency Control Plane and Never-Touched Holdout governance.
- Real Shadow creation/settlement workflow and shared frozen Shadow/Production inference path.
- Versioned additive database migrations with checksum protection.
- Locked runtime/CI dependencies and PRD v2.3 acceptance / contract-smoke Actions evidence.
- Engineering completion never implies statistical production approval; absent approved real OOS + Shadow evidence, 3D/7D/30D remain `UNAVAILABLE + Reason Code`.
